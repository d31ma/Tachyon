# Feature Parity Ledger

This ledger compares two implementations, feature by feature:

- the Rust implementation in this repository;
- the released JavaScript implementation. It is kept as the unchangeable
  v26.30.04 binary outside this branch.

People update this ledger by hand, and tools check it:

- `ty migrate check` classifies a real project with the same status words.
- `scripts/compat/differential.mjs` proves the `identical` claims. It renders
  both implementations in a real browser. Then it compares what a user or an
  assistive technology (for example a screen reader) observes.
- `TAC_LEGACY_BIN` selects the released legacy binary.
- `TAC_BIN` selects the Rust binary under test.

The legacy source tree is not in this repository, on purpose.

## How This Ledger Is Verified

`scripts/compat/verify-ledger.sh` checks the compiler and discovery
classifications with the real `ty` binary. Separate gates prove the rest:

- the named browser gates prove browser behavior;
- the target-specific gates prove native execution.

A successful compile alone does not prove runtime behavior. Run the check with:

    ./scripts/compat/verify-ledger.sh

An earlier version of this ledger was wrong about component `tac.css`. It
claimed that component `tac.css` worked because page `tac.css` worked. In fact
the component case failed. It started to work only after scoped component
styles were implemented and added to the verification script. The row below
describes the current behavior that the script runs.

## Vocabulary

| Status | Meaning |
| --- | --- |
| `identical` | Both implementations accept the same source code and produce the same observable result. The differential corpus proves it. |
| `equivalent` | Both implementations support the feature. The observable result differs only in ways that this ledger records as intentional. |
| `changed` | Supported, but the source code must change. `ty migrate check` reports the required action. |
| `unsupported` | Rust has no equivalent. Only the legacy implementation can run it. |
| `rust-only` | A convention that the Rust implementation adds. The legacy implementation has nothing like it. |

## View Layer

| Feature | Status | Notes |
| --- | --- | --- |
| `client/pages/**/tac.html` discovery and routing | `identical` | Corpus: `static-pages`, `semantic-html`. |
| **Dynamic route segments** (`_id`, `_version`) | `identical` | **Verified: implemented.** Discovery accepts `_name`. The route manifest carries the ordered `parameters`. Nested segments combine, for example `/items/_id/reviews/_review`. The compiler publishes one client render-plan template for the route pattern, and the browser owns its DOM. An invalid or duplicated name fails with `TY1006`. |
| Semantic HTML: headings, `nav`, lists, links, images, rules, `details`/`summary`, tables, `footer` | `identical` | Corpus: `semantic-html`, two routes, byte-identical semantic DOM. |
| Standard HTML void elements (`<img>`, `<hr>`, `<br>`, `<input>`) | `rust-only` | The legacy parser rejects them with "No end tag." and requires the self-closing form. The Rust parser accepts both forms, so it accepts everything the legacy parser accepts, and more. Corpus fixtures use the self-closing form so that both implementations can be compared. |
| Text interpolation `{name}` | `equivalent` | The compiler serializes the expression AST (abstract syntax tree). The Tac browser renderer escapes the resolved value for its context. |
| Dynamic attributes `:name="expr"` | `equivalent` | Same syntax, same escaping. |
| Conditionals `<logic :if>`, `<logic :else-if>`, `<logic else>` | `equivalent` | The compiler serializes them into the bounded Tac render plan. The browser resolves them reactively. The compiler selects no branch. |
| Iteration `<loop :for>` | `equivalent` | Same syntax and limits. The Tac browser renderer expands the loop. |
| Legacy `<if :when>`, `<else>` and `<for :each>` elements | `changed` | Removed on 2026-10-03 by user decision. The compiler refuses them with TY1367 and names the `<logic>` or `<loop>` form. `ty migrate fix --write` rewrites them. |
| Tac components and `<slot>` | `equivalent` | The compiler resolves component templates and slots into the client render plan. The browser creates the resulting subtree and keeps its accessible names and roles. |
| Conditional and arithmetic template expressions | `equivalent` | **Verified: implemented.** Templates support `condition ? a : b` and `+ - * /`. So a template can pick a class inline (`slug === active ? 'active' : ''`) and build a path (`'/docs/' + topic.slug`). The project's own website does this in many places. Rules: `+` joins strings when either side is a string, and adds numbers otherwise. `*` and `/` bind tighter than `+` and `-`. Division by zero gives a missing value, not infinity. A `null` alternative removes the attribute instead of printing `null`. The expression language stays bounded: no calls, no assignment, no side effects. |
| Service fields inside a component | `equivalent` | **Verified in a real browser.** A component view reads a service's fields and calls its methods by instance name. `{report.loadingState()}`, `{report.label}`, `{report.count + 1}`, `{report.rows.length}` and `{await report.note()}` all resolve against the `ReportService` instance (ADR 0030). Nothing runs as source code. The compiler emits the bounded AST that it already parsed, and the runtime interprets that fixed shape. See ADR 0015. |
| Released page class and literal `<script>` state | `changed` | **Verified in real Chromium against both web and staged native documents by `scripts/compat/standalone-rust.mjs`.** A page combines components and owns no state. Its `tac.html` holds component tags only. A page-level `<script>`, markup, companion or stylesheet fails with `TY1309`, and the message names the component to move it into (ADR 0029). State is a service's fields, and the view addresses them by instance name (ADR 0030). Lifecycle uses `@OnStart`/`@OnStop`. Owner resources are fields marked `@Needs` and named after the resource, such as `view`, `lifecycle`, `taskScheduler` and `applicationEventPublisher` (ADR 0038). The build refuses the retired `@Resource` marker and names the field to write instead. Plain code needs no decorators. The annotations are compile-time markers, not a runtime dependency. Arbitrary inline expressions, attributes and executable initializers in a component view fail with `TY1306`. |
| Service fields with `mount="never"` | `unsupported` | A component that never mounts activates no service. Move expressions that need a service into a mounted component, or pass literal props. |
| Method calls without a service (`{loadingState()}`) | `unsupported` | A call must name a service (`{report.loadingState()}`) or a handler that the component's props supply. A mount policy on a component that names no service fails with `TY1405`. |
| `<switch>` / `<case :when>` / `<case default>` | `equivalent` | **Verified: implemented.** A switch is a short way to write a conditional chain. `<case :when="a">` means `value == a`. The first match wins. `<case default>` is the else branch. The parser rewrites a switch into that chain, so the renderer, the native planner and the view IR (intermediate representation) never see a third kind of control. The parser builds the comparison node directly. It does not join source text. So a switch value like `a \|\| b` cannot change meaning through operator precedence. Each of these fails with a diagnostic that names the rule: a case after `default`, a child that is not `<case>`, and an empty switch. |
| TypeScript service (`client/services/<Name>Service.ts`) | `equivalent` | **Verified: implemented.** The TypeScript compiler itself emits a TypeScript service. So its semantics are the reference semantics, not a copy of them. A `tac.ts` beside a component view fails with `TY1310` (ADR 0030). TypeScript 6 or newer is required. An older version fails with `TY1009`, and the message names the version found. |
| Component `tac.css` | `equivalent` | **Verified: implemented, after it failed without any error for months.** A page-level `tac.css` worked, but the compiler rejected a component `tac.css` with `TY1401`. Nobody noticed because `verify-ledger.sh` only tested the page case. It now tests both. Styles are scoped with CSS `@scope`, the browser platform's own feature for component scoping. The compiler puts one `data-tac-scope` attribute on the component's root elements. It writes `@scope ([data-tac-scope="<name>"]) { ... }` into `.tachyon/components.css`. Nothing parses or rewrites a selector. The compiler does not add an attribute to every element, as `data-v-*` scoping does. A browser without `@scope` ignores the block. The component is then unstyled, but its rules do not affect other elements. The compiler emits the stylesheet and its link only when a component has one. |
| Component path convention | `identical` | A component's directory names its tag, at any depth: `clicker/` names `<clicker>`, `date-picker/` names `<date-picker>`, and `product/card/` names `<product-card>`. A tag without a hyphen is not a valid custom element name. But the compiler removes components during compilation and does not register them, so that is not a problem. The real risk is a name clash with an element that HTML has today. The compiler rejects a directory named after such an element, so a template never changes meaning without warning. |
| Component mount schedules | `equivalent` | The browser creates component DOM. It activates the services that the view names on load, idle, visibility, interaction, or never. A component that names a service defaults to load. The legacy `hydrate` attribute is accepted only as another name for a schedule. No server hydration happens. |
| `on:<event>` event bindings | `equivalent` | **Verified: implemented.** `on:click="counter.increment()"` compiles into the bounded Tac client render plan. Its browser renderer attaches the listener and calls the named service's method. A handler names one bare identifier or one `service.member`. `scripts/events-browser-test.mjs` proves this in real Chromium: handlers with no arguments, with literal arguments, and with the dispatched event all run. Binding values are parsed data. They are **never** run as JavaScript source. A page that binds named handlers without a client module fails with `TY1306`. |
| `tac.js` client module | `changed` | Discovery no longer finds a `tac.js` beside a view anywhere. Beside a page it fails with `TY1309`; beside a component it fails with `TY1310`. Behavior is a `@Service` class in `client/services/<Name>Service.js`. The compiler emits it as the module `dist/.tachyon/services/<Name>Service.js`. The components whose views name it load it (ADR 0030). |
| `tac.ts` companion | `changed` | Same move as `tac.js`: use `client/services/<Name>Service.ts`. The TypeScript compiler itself emits it, so the semantics are the reference semantics. The build requires TypeScript 6 or newer, the first version that accepts the emit flags. Tested with 5.6, 5.9, 6.0.3 and 7.0.2. An older or missing compiler fails safely with `TY1009`. See ADR 0007. |
| Target-native services | `changed` | Swift targets Apple hosts and Kotlin targets Android. Windows links C#, and the desktop hosts link Rust. A native service is `client/services/<Name>Service.swift\|kt\|cs\|rs`. The compiler builds it into the host. The host activates it for each browser-side service instance on the page's canonical route (ADR 0030). A Rust, Go, C#, Swift, Kotlin or Java service with no JS, TS or Dart file also reaches the web, and every target that does not link it, as WebAssembly (ADR 0035, ADR 0037, ADR 0045, ADR 0078, ADR 0082, ADR 0083). If a service has several, Rust wins, then Go, then C#, then Swift, then Kotlin, then Java. A Kotlin web build needs `kotlinc-js` 2.1.10 and `TAC_KOTLIN_WASM_STDLIB`, and a release build optimizes it with Binaryen's `wasm-opt` when one is installed. A Ruby service (`<Name>Service.rb`) runs on Tachyon's mruby WebAssembly runtime on every target and comes last (ADR 0049, ADR 0054); the developer's machine builds that runtime once into the Tachyon cache with Ruby, Emscripten 6.0.10 or newer and a C compiler, and without them the build fails with `TY1605`. A Rust web build needs the `wasm32-unknown-unknown` Rust target; without it the build fails with `TY1605`. A C# web build needs the .NET `wasm-tools` workload. A Swift web build needs the Swift SDK for WebAssembly (`TAC_SWIFT_WASM_SDK`) and a `swiftc` of the same version (`TAC_SWIFT_WASM_COMPILER`); without them the build fails with `TY1605`. A Java web build (`<Name>Service.java`) needs `javac` and TeaVM 0.15 (`TAC_TEAVM_HOME`); without them the build fails with `TY1605`. A Python service (`<Name>Service.py`) runs in the browser on a pinned Pyodide 314.0.7 WebAssembly interpreter. The project selects it in `client/manifest.json` with `"tac": { "python": { "runtime": "pyodide-314.0.7", "profile": "offline" } }`. ty never downloads Python. The five core files of the official `pyodide-core-314.0.7.tar.bz2` archive must already be in the Tachyon cache, and ty checks the size and SHA-256 hash of each file; without them the build fails with `TY1605`. Python services support synchronous methods only. Async methods, browser capability adapters and native hosts do not support Python yet. See `CLIENT_RUNTIME_MIGRATION.md`. |
| General inline `<script>` in a view | `unsupported` | Executable inline code, imports and scripts with attributes fail with `TY1306`. The one exception for compatibility is the literal Tac page-state declaration described above. Behavior belongs in a client module. Yon has no view source. |
| Native `onclick=` attributes | `unsupported` | Verified: fails with `TY1306` and tells authors to use `on:<event>`. The legacy compiler does the same: it also refuses to leave raw `on*` handlers in the DOM. |
| `$event` in an `on:<event>` binding | `equivalent` | **Verified in a real browser.** A binding may pass `$event` or a bounded dotted path on it, as in `on:input="setField('email', $event.target.value)"`. Vue, Angular and Alpine all use the name `$event`, and the project's own website already uses it. The compiler parses the binding into a structure and emits it as JSON. It never runs it as JavaScript, so the no-script rule still holds. Paths are plain identifiers, at most four segments deep. `scripts/events-browser-test.mjs` proves this with a real input. |
| Render-scope arguments in an `on:<event>` binding | `equivalent` | When the event fires, event arguments resolve from the binding's lexical render scope. This includes local variables of nested loops and bounded `$event` paths. No expression source runs. Browser global variables do not enter the expression scope. |
| Assignment in an `on:<event>` binding | `equivalent` | `on:input="basket.query = $event.target.value"` updates the named service and renders the client-owned document again. Native field assignments go through `companion.invoke` before the new render. When a host write fails, the runtime reports the failure. It does not treat the write as successful. Browser regression test: `scripts/runtime-browser-test.mjs`. |
| `tac.css` / `yon.css` colocated styles | `identical` | **Verified: implemented.** The compiler writes it beside the owning route as `style.css`, and the document links it. Reused routes keep it. A change to one of these files makes its route build again. |

## Server Layer

| Feature | Status | Notes |
| --- | --- | --- |
| Request correlation identifiers | `identical` | **Verified:** dispatched requests carry a TTID. Tachyon computes it natively; it does not start a process per request. Ids from Rust match the unchangeable v26.30.04 wire behavior and decode to their true creation time. |
| Route parameters delivered to handlers | `identical` | **Verified:** Handler Protocol v1 carries an optional `parameters` map. The map is absent for a static route. |
| `server/routes/**/yon.js` handlers | `equivalent` | Rust supervises one bounded process per request under Handler Protocol v1. `GET()` may take zero parameters. Operators may instead select a Firecracker control driver, but only through parent environment variables. Application source and requests cannot weaken that deployment policy. The driver transport currently accepts JavaScript and Python only. TypeScript and prepared direct-language paths fail safely before the driver starts. Tachyon does not claim hardware isolation without separate evidence from the driver and the host. |
| `server/routes/**/yon.py` handler signature | `changed` | **Verified:** Tachyon calls Python's `GET` as `GET(request)`, so it must declare the parameter. The JavaScript adapter accepts zero parameters. |
| `server/routes/**/yon.py` handlers | `equivalent` | Same protocol and limits. |
| Yon language set and controller conventions | `changed` | JavaScript, TypeScript, Python, Java, Groovy (ADR 0072), C#, Kotlin, PHP, Rust, Dart, Go and Ruby declare routes through `RequestRoute` controllers in `server/controllers/` (ADR 0048). Shared same-language role files supply providers, dependencies and lifecycle hooks. Go uses comment annotations such as `// @Service` (ADR 0050), and Ruby uses comment-line annotations such as `#[Service]` with YARD types (ADR 0054). Invalid declarations, unresolved dependencies, cycles, scope capture and duplicate registration fail before invocation. Plain HTTP-verb-named `Handler` route files are retired; workers and root middleware retain their separate contracts. Real-runtime tests provide evidence for this Rust-only behavior. |
| Programs in any other language | `changed` | They are not routes, middleware or workers. Call them explicitly with `relay(command, request)` or name them in a `@Gateway` command. Relay does not use a shell. It reads bounded stdout and stderr at the same time. Its deadline is the time left in the request, and every relay in a request shares it. It gets the baseline environment, the explicit allowlist, `YON_HANDLER_PROTOCOL` and its handler's `NO_PROXY` values, never `YON_APPLICATION_JSON` or a `YON_RESOURCE_*` value; this prevents accidental inheritance and is not a sandbox. Every failure reaches the handler as HTTP 502 with the fixed message `Component invocation failed.` It hides process details. It cleans up the process group of the owning handler. **Verified:** `crates/tachyon-core/tests/it/relay_boundaries.rs` in the eleven languages that have `relay` (Go spells it `Relay`). |
| Calling a method in another language (`@Gateway`) | `rust-only` | **Verified:** a Yon method declared with `@Gateway` is answered by a class in another Yon language or by a program under `server/helpers/` (ADR 0042). Arguments and results are bounded JSON; failures are four fixed kinds; one hop only; refused under Firecracker. `crates/tachyon-core/tests/it/gateway_classes.rs` and `gateway_commands.rs` run real callers and targets; `scripts/compat/verify-ledger.sh` checks the command-file and `server/gateways/` refusals. |
| `.tachyonrc` interpreter registration | `unsupported` | The `interpreters` object fails safely with `TY1502` and tells you to move to `relay(...)`. Shebang and executable-handler fallbacks are also removed. The `workers` object is still supported. |
| Handler importing application modules | `changed` | **Verified:** JavaScript, TypeScript, Python and PHP may import captured ordinary modules in the same language, without decorators or framework layer checks. Java, Kotlin, C# and Rust keep helper types in the route source. Builds capture server modules but never run them. |
| `server/routes/**/yon.html` views | `unsupported` | Yon is REST-only. Discovery rejects `yon.html` with `TY1008`. The message tells the developer to return an explicit `text/html` response from a handler. |
| Route context from static handler fields and `GET()` | `unsupported` | ADR 0016 removed it. A handler method runs only for a request or an explicit call, and its return value is the HTTP response. |
| Root middleware | `changed` | **Verified for before and after phases.** Middleware uses one of the Yon languages and declares one class named `Middleware`. The runtime calls its `before(request)` before the route and its `after(request)` after it, for every request, whatever its HTTP method. Go spells them as the exported methods `Before` and `After`. A missing method lets that phase pass. A `Handler` class in a middleware file fails with `TY1310`. Returning 204 continues. Another status answers early. The after phase may merge or replace a response. Arbitrary `.tachyonrc` middleware interpreters are removed. |
| `server/workers/**` background workers | `changed` | **Verified:** `.tachyonrc.workers` still declares bounded intervals of 1–86,400 seconds. Scheduling reuses handler supervision. Worker sources now use one of the ten Yon languages. Registration no longer accepts arbitrary interpreters. |
| Native generator handler methods | `rust-only` | JavaScript, TypeScript, Python, PHP, Kotlin, C#, F#, Dart, Ruby, Lua, Go and Rust stream when an HTTP method uses the language's own generator/yield syntax (Lua `coroutine.yield`, a Go `iter.Seq`, a Rust `impl Iterator`). Each yield becomes one bounded SSE (server-sent events) event. Java and Groovy return a single response. No marker can disagree with the body. A timeout or a subscriber disconnect ends the whole process group. |
| HTTP handler dispatch | `equivalent` | **Verified: implemented.** The server matches a request path against the route graph, binds dynamic parameters, and calls the supervised handler for each request. `crates/tachyon-core/tests/it/dispatch.rs` proves this over a real socket: parameter binding, percent-decoding, request bodies, multiple methods, explicit byte-preserving `text/html` responses, 405 for a method the handler does not implement, 404 for unknown paths, and resistance to path traversal. Production work (pooling and keep-alive tuning) is still open. |
| Realtime and topic logs | `equivalent` | **Verified: implemented. It follows the released protocol instead of replacing it.** In the v26.30.04 design, each topic is an append-only NDJSON log. A client reads it with an integer-position cursor over server-sent events. Tachyon keeps that contract. A topic is `data/topics/<topic>.jsonl` (the folder is `topics.directory` in `server/application.json`; before 2026-09-28 it was `.tachyon/topics`, and the server moves old logs once). `GET /.tachyon/topics/<topic>` streams it as `text/event-stream`, and each frame carries its position as the event id. To publish, a handler appends a line, so a handler in any language can publish without a client library. A new `EventSource` without a cursor starts at the oldest kept replay record. When a browser reconnects, it sends `Last-Event-ID` and continues at the next record. Clients that are not browsers may send an explicit `?position=`. If an explicit cursor points to a removed record, the stream closes with a named JSON `topic-error`. The client can then create the source again without that cursor. Limits: 128 connections in total, 32 per topic and 32 active topics. Replay keeps 256 records. Each record is at most 64 KiB, and the log is at most 16 MiB. When capacity runs out, the server answers HTTP 503. The client must close and retry a bounded number of times. There is no WebSocket upgrade, because the released realtime feature does not use one. |
| Telemetry and OpenTelemetry spans | `out-of-scope` | **Excluded by an explicit product decision.** The archived JavaScript release emitted telemetry spans. The Rust implementation does not. A project that depends on emitted spans must add instrumentation outside Tachyon or stay on the archived release. Structured request logging is a separate topic, and this row does not cover it. `ty migrate check` reports use of the archived built-in telemetry feature, so a migration does not lose it without notice. |
| OpenAPI generation and `/api-docs` | `out-of-scope` | **Excluded by an explicit product decision. It was not excluded because nobody used it.** The archived release served OpenAPI 3.1 at `/openapi.json` and a client at `/api-docs`. A project that relies on those endpoints must generate a specification another way or stay on the archived release. Review this decision again if the trade-off is not wanted. |
| Every legacy command name (`init`, `serve`, `bundle`, `native-bundle`, `preview`, `cache`) | `changed` | **Verified by the released standalone workflow.** The CLI accepts existing command names, target aliases, target and environment selection, host and port environment variables, `--no-bundle`, `--skip-package`, and one or many bundle targets. The packaging override is now `TAC_DIST_PATH`. Qualification of the archived v26.30.04 release still uses its legacy spelling `YON_DIST_PATH`. Removed render-mode inputs for the whole application fail with a diagnostic that explains how to move to the native web view. |
| `ty init` scaffold | `changed` | **Verified against 26.30.04 with declared migrations.** The scaffold keeps the plain `Handler` route convention. It removes the legacy database layout and the environment defaults that only the JavaScript server used. It normalizes the installer sentence that only the standalone release had. Byte comparison skips the new ambient type contract. Rust scaffold tests cover the generated contract. New projects contain only environment settings that the Rust CLI reads, and no legacy database layout. |
| `ty cache status` / `ty cache clean` | `intentional` | **Verified by the standalone workflow.** The Rust binary keeps the cache directory, the `runtime/native-v1` entry, the status wording and the clean lifecycle. It standardizes the override as `TAC_CACHE_DIR`. Its native runtime does not need to extract JavaScript. |
| Offline static cache | `changed` | **Verified in a real browser.** `/tachyon-sw.js` caches only two kinds of responses: packaged assets whose fingerprint it verified, and anonymous public API reads that are explicitly configured. Packaged documents are network-first. Other packaged files are cache-first. Requests that carry credentials, an Authorization header or no-store skip the cache and remove matching entries. The cache excludes private, no-store and Vary responses. Limits: static bodies 4 MiB, API bodies 256 KiB, the whole cache 256 entries and 32 MiB. Loopback and native hosts do not register the service worker. `scripts/service-worker-browser-test.mjs` proves the privacy exclusions, the fingerprint checks on writes and on hits, the native exclusion, and offline rendering of documents and styles. |
| Legacy component re-render registry | `changed` | **Replaced by the bounded Tac client renderer.** Components render in the browser from plans that the compiler owns. Semantic hot updates replace named component boundaries through that renderer and transfer a bounded amount of state. There is no general registry of render closures owned by the application. |
| `ty migrate check` accuracy | `equivalent` | **Verified: it runs the compiler instead of guessing.** The old classifier looked only at file names. It once reported 142 supported, 1 changed and 7 unsupported, while the website build failed with 97 diagnostics. Views now go through the real parser, and its diagnostics become findings word for word. After the website migration, the command reports 128 supported, 1 changed and 1 unsupported, and the same sources build successfully. Rules at file and project level still cover what no view shows. |

## Developer Loop

| Feature | Status | Notes |
| --- | --- | --- |
| Source watching and rebuild on change | `rust-only` | **Verified: implemented.** `ty dev` uses operating-system events, a bounded queue and a 75 ms quiet period. It does not walk the source tree again and again. A failed rebuild publishes Diagnostics v1 and keeps the previous output and DOM running. `--no-watch` turns off the watcher and the injected client. |
| Semantic hot updates | `rust-only` | **Verified in a real browser.** Hot Update Protocol v1 streams over SSE. What happens depends on the change. A CSS change keeps state. A service change (boundary `service:<Class>`) aborts and disposes the old browser-owned instance in every component that names it. It loads code addressed by digest. It restores declared service state and a bounded amount of form, disclosure, scroll and focus state. Invalid source shows diagnostics over the last good page. Structural and mixed changes reload the page safely. `scripts/hot-update-browser-test.mjs` is the repeatable browser gate. See ADR 0015. |
| Single-page navigation | `changed` | **Deliberate difference.** Tac renders each route in the browser, but navigation stays browser-native and moves between documents. View transitions and same-origin speculation prefetching make navigation smooth without a client router. In-memory state does not survive a navigation. Use storage, a shared worker or the server. See ADR 0015. |

## Native

| Feature | Status | Notes |
| --- | --- | --- |
| macOS, iOS, Linux, Windows, Android applications | `changed` | Each application hosts the compiled Tac document in WKWebView, Android WebView, WebKitGTK or WebView2. The old architecture, with Native UI control adapters and a fallback per subtree, is retired. Old phase evidence is history. It does not qualify this host version. See `SUPPORT_TIERS.md`. |
| Target-native services | `changed` | `client/services/<Name>Service.swift` (Apple), `.kt` (Android), `.cs` (Windows) and `.rs` (desktop) compile with the target's toolchains. The build selects the most specific available language. On the web, a JS, TS or Dart file is used first; otherwise a Rust, Go, C#, Swift or Kotlin service runs as WebAssembly (ADR 0035, ADR 0037, ADR 0045, ADR 0078, ADR 0082) and reaches the browser APIs through Tachyon (ADR 0065). |
| Per-instance native service state and invocation | `rust-only` | `scripts/native/companion-test.mjs` builds the project with the selected binary and runs its generated native ABI (application binary interface). It verifies separate state per instance, reads and writes, methods, native OS access, rejection of unknown routes and unknown services (`TY_NATIVE_SERVICE`), and host publish callbacks. Separate platform UI gates verify the web-view transport. |
| Native asynchronous browser bridge | `changed` | The compiled plan identifies the canonical route. Initialization reads declared fields but never runs methods. Calls happen only when code calls them explicitly. Setters finish before the new render, and method calls refresh field state. Requests and responses are bounded. Failures return cleaned (sanitized) errors. |
| Former fixed JS host verbs | `changed` | `host.on`, `shortcuts.register` and `contentSurface.open/state` belonged to the retired widget host. Instead, use platform SDKs from a target-native service, native publication and an `@OnEvent` method. Tachyon does not quietly emulate these verbs. The injected `WindowControls` browser API is limited to declared window controls (ADR 0087). |
| Native-to-Tac signals | `rust-only` | The local host queues publications that arrive early. The client reads at most 128 records into the retained bus of the document. This is not a network or SSE topic subscription. |
| Former browser Wasm companions, including Dart | `changed` | The old Wasm (WebAssembly) companion ABI and loaders are retired, and so is a `tac.dart` beside a view. The web still uses WebAssembly, in a new form: a Rust, Go or C# service with no browser script is compiled into one WebAssembly module that the page hosts and that speaks the same companion protocol as a desktop host (ADR 0035, ADR 0037). Dart browser services compile to WasmGC behind a JavaScript bridge (ADR 0033). Move OS-specific behavior to a target-native implementation of the service. Python is not a Tac service language; where it fits, it can stay as an explicit Yon relay program. Historical ADR 0011 is not the current API. |
| `ty doctor` | `rust-only` | Reports the requirements of the selected native and TypeScript toolchains. It does not register arbitrary interpreters. It checks the `wasm32-unknown-unknown` Rust target and the .NET `wasm-tools` workload only when a Rust or C# service needs them on the web, and the Go toolchain when a Go service does. |
| Capability Manifest v1 and Artifact Manifest v1 | `rust-only` | Versioned contracts record the target and bridge version, where inputs came from, generated outputs and digests. Source discovery and publication keep the captured-input and atomic-output boundaries. |
| Remote content | `changed` | Only the packaged local application gets the privileged bridge. A remote document or subframe never gets it. Host navigation and frame checks enforce that boundary. |

## Restored Client Runtime

| Feature | Status | Notes |
| --- | --- | --- |
| `this.tac` runtime API | `changed` | Removed, with no alias (ADR 0028). Its verbs became owner-bound resources; `invalidate` became `@ClearCache` and `@UpdateCache` on HTTPClient methods (ADR 0087). A `@Needs` field receives each resource by its Spring name (ADR 0038): `resourceLoader` (precache/clearAssetCache), `taskScheduler` (render), plus `view` and `lifecycle`. Resources are injected after construction. They do not appear in state snapshots (non-enumerable). They grant no native capability. Hot state stays cloneable. |
| `$` / `$$` field persistence | `changed` | Fields marked `@SessionState` use per-tab session storage and fields marked `@LocalState` use origin-local persistent storage; the prefixes are refused and `ty migrate fix` converts them (ADR 0059). If storage is denied, over quota or malformed, the field falls back to its in-memory default. `scripts/storage-browser-test.mjs` proves reload and tab behavior and failure handling. |
| Response caching and invalidation | `changed` | HTTPClient reads are sent `no-store`. A read marked `@Cached` (with `@CacheSettings` on the class) is kept in the behavior cache, and `@ClearCache` or `@UpdateCache` on a write changes it (ADR 0087). The former `cache` option and its IndexedDB store are removed and refused by name. In JavaScript and TypeScript a `Cached` GET is a public read that the service worker may keep by the `tac.cache` rules. |
| `mount()` / explicit publish and subscribe | `changed` | `@OnStart` replaces `mount()` and runs once the owner DOM exists. `@OnStop` runs on removal and on HMR (hot module replacement). An injected `applicationEventPublisher` field publishes a model value with `publishEvent(model[, retain])`. `@OnEvent` (with optional `replay`, `condition` and `id`) receives exactly one payload of the model type of its parameter (ADR 0055). `@Order(n)` sets the order of listeners, and `@InBackground` can defer a listener (ADR 0031). Listeners register before initialization. Payloads are finite JSON, at most 64 KiB, and each listener gets its own copy. Retention and replay are opt-in. Retired decorators and the old hook fail with migration guidance. |
| Retained signals and subscription ownership | `rust-only` | Topics, listeners and retained values are local to the document and bounded. Abort, component removal and HMR dispose subscriptions. Errors from synchronous and asynchronous subscribers are isolated, and payloads are not logged. Native publish uses the same bus. |
| Counted loops | `rust-only` | `<loop :for="let i = 0; i < 3; i++">` supports ascending and descending bounds and positive step sizes. A loop runs at most 10,000 iterations. Total iteration and node budgets also limit nested empty loops. A step that makes no progress fails safely. Legacy spellings for iterables and control tags are still accepted. `scripts/runtime-browser-test.mjs` tests dynamic bounds, invalid steps, scope, limits and recovery. |
| Ordinary JS/TS module helpers | `changed` | Top-level constants, helper functions and imports stay legal in plain modules, such as files in `shared/`. An annotated file, a Yon handler and a worker hold one class and its imports ([ADR 0044](adr/0044-an-annotated-file-holds-one-class.md)), so their helpers move to `shared/`, `models/` or a service. Native reflection has its own boundary for each language. |

## What the Ledger Does Not Claim

- No row claims that a Rust feature is ready for production. `SUPPORT_TIERS.md`
  decides readiness.
- `unsupported` never means "will not be supported". It means that Rust has no
  equivalent today, and the legacy implementation is still required.
- The differential corpus covers only features that both implementations can
  build. Features marked `rust-only` have no legacy counterpart. The Rust phase
  suites prove them instead.
