# ADR 0016: Yon Is REST Endpoints Only

- Status: Accepted
- Date: 2026-08-10
- Supersedes: the `yon.html`, Yon view-context, and Yon server-rendering
  portions of ADR 0002 and the Phase 1/3 specifications

## Context

Yon owns server routes and supervised handler execution. An experimental
rewrite feature also treated `server/routes/**/yon.html` as a template,
executed colocated `GET` handlers during compilation through a private
`view.context` operation, merged their values, and server-rendered the result.

That design violated the endpoint boundary. It made an HTTP method execute at
build time, assigned two meanings to a handler return value, and made REST
routes participate in a view compiler without an explicit response decision.

## Decision

Yon is exclusively an HTTP endpoint framework.

- `server/routes/**/yon.*` files are handler sources.
- Handlers execute only for an HTTP request, worker/middleware lifecycle, or an
  explicit `ty handler invoke` operation.
- Ordinary JavaScript and Python handler return values become JSON responses.
- A handler may return an explicit `{status, headers, body}` descriptor.
- HTML requires an explicit `Content-Type: text/html` header and the supplied
  body is transported unchanged.
- Yon never parses, interpolates, escapes, expands components in, or evaluates
  structural tags in an HTML response.
- `yon.html` is rejected with `TY1008` and an actionable migration message.
- The private `view.context` operation, populated route-context declarations,
  server template evaluator, and build-time handler execution do not exist.
- Route Manifest v1 retains its required `context` member with empty export
  lists solely for wire compatibility; it declares no executable behavior.

Tac remains the only view frontend and remains exclusively client-rendered.

## Consequences

- Builds are deterministic without executing endpoint code.
- `GET` has one meaning: handling a GET request.
- Response content type is an explicit application decision.
- An HTML response can be generated by application code or another library,
  but Tachyon treats it as opaque response data.
- Route Manifest v1 publishes only the deprecated empty context shape. A
  future Route Manifest v2 may remove the member with an explicit migration.
- Previous Yon-template fixtures and documentation are invalid and must migrate
  to Tac pages or explicit Yon HTTP responses.

## Rejected Alternatives

- **Render `yon.html` only when a handler chooses `text/html`**: still gives Yon
  a hidden template engine and conflates a response body with a source file.
- **Run `GET` during build only for static routes**: violates HTTP method
  semantics and makes builds execute application side effects.
- **Keep populated route context as a deprecated behavior**: would advertise
  and preserve build-time handler execution. The empty v1 wire member remains
  only because the published contract is immutable.

## Acceptance Gate

- discovery rejects `yon.html`;
- builds do not invoke Yon handlers;
- ordinary handler values remain JSON responses;
- explicit `text/html` responses preserve status, headers, and body without
  template processing or Tac runtime injection;
- no production server renderer or server expression evaluator remains; and
- Route Manifest v1 accepts and emits its deprecated empty context shape; and
- canonical format, check, Clippy, test, documentation, dependency-policy, and
  HTTP dispatch gates pass.
