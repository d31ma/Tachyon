# ADR 0018: Native Hosts Run the Platform's Web Engine

- Status: Accepted
- Date: 2026-08-30
- Reconciles: the unshipped native-host decision dated 2026-08-21
- Amends: the native-planning paragraph of ADR 0015

## Context

The released widget planner and the newer local native implementation diverged.
The planner lowered a subset of Tac into platform controls, but could not give
reactive browser components or application-owned native companions equivalent
behavior. A native application must execute the same client render plan as the
web application, not a server-rendered or separately inferred widget tree.

## Decision

Every native host loads the application's staged web bundle in its platform's
web engine: WKWebView on macOS/iOS, WebKitGTK on Linux, WebView2 on Windows,
and Android WebView. JavaScript/TypeScript browser code remains browser code.
The host provides a small named JSON capability bridge; it is not a general
reflection, shell, filesystem, or remote-code execution interface.

Navigation and messages are restricted to the local application origin and
the main application frame. Bundle asset resolution must support root-relative
URLs without exposing arbitrary filesystem paths. Untrusted remote pages and
subframes cannot inherit native capabilities.

Compiled page companions are selected per canonical route, never globally
from the first page. The bounded route registry is generated by the compiler;
route identifiers received over the bridge are checked against it. See
[ADR 0019](0019-companions-compile-for-their-target.md).

## Consequences

- Native UI rendering follows the same client-only ownership as the browser.
- Hosts build on their target operating system with that platform's SDK.
- Windows uses MSVC and WebView2, not a MinGW widget implementation. The
  WebView2 runtime and redistributed loader are explicit prerequisites.
- Native companions are trusted application code. The bridge's origin, route,
  operation, payload, lifecycle, and capability checks remain security boundaries.
- The older Native UI widget planner is superseded, not silently retained as
  an alternative renderer. Its historical ADRs remain available for audit.

## Acceptance

Native gates must launch actual generated applications, exercise DOM events,
load root-relative assets, dispatch two distinct page companions, and reject
foreign-frame/origin messages. Source-string checks supplement but do not
replace platform build and execution gates.
