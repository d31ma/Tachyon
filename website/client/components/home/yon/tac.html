Yon backend

Filesystem routes, polyglot handlers, production guardrails.

Yon is Tachyon's server runtime. Drop yon.<ext> files under server/routes, export a Handler class or executable protocol adapter, and Tachyon wires HTTP methods, bounded process supervision, middleware and request identifiers around each request. 

ty init api --name "My API"
cd api
mkdir -p server/routes/health
ty serve

ty serve detects whether the app has client/, server/, db/, or a mix, then serves the right runtime on one port.

ty serve
YON_PORT=8000 ty serve
NODE_ENV=production ty serve

Handlers return protocol responses. Yon binds route parameters, supervises the process, preserves headers and bodies, and reports bounded failures consistently.

export class Handler {
  static GET() { return { ok: true } }
  static POST(request) { return request.body }
}

Any executable language can read one bounded JSON request from stdin and write one JSON response to stdout; .tachyonrc registers interpreters.

server/routes/items/
  yon.rb
.tachyonrc

Handlers append NDJSON records to bounded topic logs; browsers subscribe with EventSource and resume from the last event position.

new EventSource('/.tachyon/topics/releases')

Root middleware uses the same supervised protocol as handlers. Return 204 to continue, answer early from before, or merge response headers in after.

server/middleware/yon.rb
.tachyonrc

Yon serves loopback by default with security headers, rejects path traversal, bounds bodies and handler time, and emits stable diagnostics when a process fails.

ty serve
ty doctor
ty migrate check

Built-in ergonomic adapters

Yon can run any executable handler that speaks its JSON stdin/stdout protocol. JavaScript and Python also get the class Handler convenience path; every other language keeps its ordinary executable semantics.
